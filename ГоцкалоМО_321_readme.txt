Этот репозиторий содержит реализацию двух детерминированных подходов к построению многопроцессорного расписания с минимизацией длительности (makespan) при жёстком ограничении на суммарный объём памяти, используемой для хранения промежуточных данных (буферов):

1. **Жадный алгоритм** списочного планирования с двумя эвристиками:  
   - EFT (Earliest Finish Time)  
   - STS (Smallest Time Space)  
2. **Точный метод** на основе целочисленного линейного программирования (ЦЛП) с использованием решателя SCIP.

Включает в себя инструменты для генерации графов работ, конвертации в формат с буферами, подбора параметров вычислительной системы ($P$, $M$), трансляции графов во входной язык решателя, запуска экспериментов, обработки результатов и визуализации расписаний.

## **Сборка проекта**

Программная реализация жадных алгоритмов (C++) использует систему сборки CMake.

**Требования:**
- Компилятор с поддержкой C++17 (gcc, clang, Apple Clang)
- CMake версии 3.10 или выше
- Библиотека Boost (необходима для работы с графами)

**Инструкция по сборке:**

1. Перейти в корневую директорию проекта (где находится `CMakeLists.txt`).
2. Создать каталог для сборки:
   ```bash
   mkdir build && cd build
   ```
3. Запустить CMake:
   ```bash
   cmake ..
   ```
4. Выполнить сборку:
   ```bash
   make
   ```
   (на macOS или Linux; на Windows может потребоваться указать генератор).

В результате в каталоге `build` будет создан исполняемый файл `application`. Именно он используется для запуска жадных алгоритмов (как вручную, так и через скрипт `running_all_experiments.py`).

> **Необходимые изменения в коде:**  
> При сборке может потребоваться указать путь к установленной библиотеке Boost. Для этого при вызове `cmake` добавьте флаг:
> ```bash
> cmake -DBOOST_ROOT=/путь/к/boost ..
> ```
> Также убедитесь, что в `CMakeLists.txt` правильно прописаны пути к заголовочным файлам и библиотекам.

## **Подготовка входных графов**

### Генерация графов в «старом» формате

Скрипты генерации создают ориентированные ациклические графы (DAG) без буферов:

- `layered_generator.py` – слоистые графы  
- `random_generator.py` – случайные графы (не более 2 предков, 6 потомков)  
- `triadag_generator.py` – треугольные графы (метод Гаусса–Жордана)

**Пример запуска:**  
`python layered_generator.py`

Выходной формат:  
`<номер вершины> <вес> <список потомков>`

> **Необходимые изменения в коде:**  
> В каждом генераторе в конце файла присутствует строка открытия файла для записи, например:  
> `f = open(f'/Users/.../layered_{num_of_v}.txt', 'w')`  
> Необходимо заменить этот путь на каталог, предназначенный для сохранения сгенерированных графов.  
> Также можно изменить диапазон размеров графов, отредактировав переменную `num_of_v` или `num_of_layeres`.

### Конвертация в формат с буферами

Скрипт `converter.py` преобразует «старый» формат в новый, добавляя случайные длительности работ и веса буферов, а также формируя два варианта группировки рёбер в буферы:

- **Один буфер** – все исходящие рёбра объединены (суффикс `_1.txt`).  
- **Корневое равномерное распределение** – количество буферов = $\lceil\sqrt{\text{outdeg}}\rceil$, рёбра распределяются равномерно (суффикс `_N_uniform.txt`).

**Параметры:**  
- `--time-min`, `--time-max` – диапазон длительностей работ (по умолч. 10–100)  
- `--weight-min`, `--weight-max` – диапазон весов буферов (по умолч. 1–100)  
- `--seed` – для воспроизводимости

**Пример запуска:**  
`python converter.py input_dir/ output_dir/ --seed 42`

> **Необходимые изменения в коде:**  
> Данный скрипт полностью управляется через аргументы командной строки, поэтому правка его внутренностей не требуется. Достаточно указать правильные пути `input_dir` и `output_dir`.

### Подбор параметров $P$ и $M$

Скрипт `finding_M_and_P.py` для каждого графа вычисляет:

- $P_{\max}$ – максимальное число процессоров, которое может эффективно использовать жадный алгоритм при избыточной памяти.  
- $M_{\max}$ – пиковое использование памяти при избыточном числе процессоров.

На основе этих значений формируются 9 вариантов входных данных ($3\times3$ комбинации $P$ и $M$). Для малых графов поиск $M_{\min}$ ведётся с шагом 1, для больших – шаг $\lfloor M_{\max}/100\rfloor$.

**Пример запуска:**  
`python finding_M_and_P.py`

> **Необходимые изменения в коде:**  
> В начале файла необходимо задать переменные:  
> ```python
> directory = '/Users/.../new_triadags_time'          # папка с исходными графами (уже конвертированными)
> directory3 = directory + '_P_and_M'                # выходная папка
> dirs = ['/Users/.../decision_quality/new_layered_time', ...]   # список папок для обработки
> ```  
> Следует заменить все пути на актуальные для используемой системы.  
> Для выбора режима поиска $M_{\min}$: по умолчанию `min_M_usage = 1`, `gap = 1` (для малых графов).  
> Для больших графов рекомендуется раскомментировать строки `min_M_usage = max_M_usage // 10` и `gap = max_M_usage // 100`, а текущие закомментировать.

## **Транслятор во входной язык решателя**

Скрипт `make_input_times_step2_2.py` считывает граф в новом формате (с буферами, длительностями) и генерирует описание задачи ЦЛП на языке `lp` для решателя SCIP. Для каждого графа создаются 8 файлов (4 упорядочения $\times$ 2 варианта транзитивности). Упорядочения:

- `default` – исходный порядок строк и потомков  
- `up_right` – строки снизу вверх, потомки слева направо  
- `down_left` – строки сверху вниз, потомки справа налево  
- `tiers` – по возрастанию яруса  

Флаг `-tr` добавляет транзитивные ограничения.

**Структура `.lp`-файла:**

| Секция         | Переменные / ограничения                                           |
|----------------|----------------------------------------------------------------------|
| `Minimize`     | `l` (makespan)                                                      |
| `Subject to`   | (1)–(2), (7), (10)–(11), (12)–(15) и др. (линейные ограничения)     |
| `Bounds`       | `m_{ii}=1`, `m_{ij}=1` для $(i,j)\in E$ (включая транзитивные)      |
| `Integer`      | $s_i$, $\text{start}_{ij}$, $\text{max\_end}_{ij}$, $l$              |
| `Binary`       | $m_{ij}$, $p_{ri}$, $t_{ij}$, $z_{ij}^{pq}$, $a_{ij}^{pq}$ и др.     |
| `End`          |                                                                      |

**Пример запуска:**  
`python make_input_times_step2_2.py -i graph.txt -o outputs/`

> **Необходимые изменения в коде:**  
> В конце файла (в блоке `if __name__ == "__main__"`) находятся глобальные переменные `P` и `M`, например:  
> ```python
> M = 1500
> P = 2
> ```  
> При одиночном запуске значения можно задать непосредственно здесь. Однако при массовом запуске (см. следующий скрипт) они будут автоматически заменены на значения, извлечённые из имени файла.

## **Массовая подготовка входных данных для экспериментов**

Скрипт `run_many_make_inputs_time_for_LP.py` автоматизирует вызов транслятора для всех графов из каталога. Из имени каждого файла извлекаются значения $P$ и $M$, которые подставляются в глобальные переменные скрипта-транслятора.

**Пример запуска:**  
`python run_many_make_inputs_time_for_LP.py`

> **Необходимые изменения в коде:**  
> В начале файла необходимо указать:  
> ```python
> prev_p = 'P = 6'         # текущее значение P в make_input_times_step2_2.py (для замены)
> prev_m = 'M = 968'       # текущее значение M
> directory = '/Users/.../mix22'   # папка с файлами вида имя_..._P_M.txt
> ```  
> Путь `directory` должен указывать на каталог, содержащий уже сгенерированные файлы с суффиксами `_P_M.txt`.  
> Также требуется поправить вызовы `python` и пути к каталогам `inputs/new_no_tr/order` и `inputs/new_tr/order` внутри `os.system()` – они должны вести к установленному экземпляру SCIP.

## **Запуск решателя SCIP**

Скрипт `run_many_solvers.py` управляет выполнением серии экспериментов. Для каждого графа он вызывает обёрточный скрипт `run_scip2.sh`, который:

- Запускает 8 экземпляров SCIP параллельно (по одному на каждую комбинацию упорядочения и транзитивности).  
- Лимит времени задаётся в файле `only_time.set` (по умолчанию 3600 секунд).  
- Как только один экземпляр находит оптимальное решение (`optimal solution found`), все остальные принудительно завершаются.

**Пример запуска:**  
`python run_many_solvers.py`

Логи сохраняются в каталоги:  
- `logs/new_tr/` и `logs/new_no_tr/`  
- `outs/new_tr/` и `outs/new_no_tr/`

> **Необходимые изменения в коде:**  
> В `run_many_solvers.py` необходимо задать:  
> ```python
> directory = '/Users/.../mix22'                # папка с файлами имя_..._P_M.txt
> directory2 = '/Users/.../translator_inputs'  # каталог, куда копируются графы для SCIP
> ```  
> В скрипте `run_scip2.sh` следует указать:  
> ```bash
> SCIP_DIR="$HOME/.../SCIPOptSuite-9.2.1-Linux"   # путь к установленному SCIP
> ```  
> Файл `only_time.set` должен находиться в `$SCIP_DIR` (содержит строку `limits/time = 3600`).  
> При необходимости лимит времени можно изменить.

## **Обработка результатов и формирование JSON**

Скрипт `file_reader_and_making_json.py` извлекает из логов SCIP значения переменных:

- $s_i$ – время старта работы $i$  
- $p_{ri}$ – номер процессора, назначенного работе $i$  

Вычисляет makespan как $\max_i(s_i + d_i)$ и записывает результат в JSON-файл, совместимый по структуре с выходом жадных алгоритмов.

**Пример запуска:**  
`python file_reader_and_making_json.py`

> **Необходимые изменения в коде:**  
> В начале файла необходимо задать:  
> ```python
> directory = "/Users/.../G"        # папка с исходными графами (в новом формате)
> ```  
> В теле скрипта присутствуют абсолютные пути к логам SCIP (например, `logs/new_tr/...`). Их требуется заменить на пути, соответствующие используемой файловой системе.  
> Также в конце файла указан путь для сохранения JSON:  
> ```python
> fff = open(f'/Users/.../build/Answer/lp/schedules/best/{file}.json', 'w')
> ```  
> Этот путь необходимо изменить на желаемый выходной каталог.

## **Запуск жадных алгоритмов**

### Ручной запуск

После сборки проекта (см. раздел «Сборка проекта») в каталоге `build` появляется исполняемый файл `application`. Для запуска жадного алгоритма на одном графе используется команда:

```bash
./build/application --command run --algo greedy --input /путь/к/каталогу/с/графами --output /путь/для/сохранения/расписаний --processors P --memory M
```

где:
- `--algo greedy` – жадный алгоритм с эвристикой EFT; для STS используется `--algo greedy2`
- `--input` – каталог, в котором лежит один файл `.txt` с описанием графа (в новом формате)
- `--output` – каталог, куда будут сохранены результаты (JSON-файл с расписанием)
- `--processors P` – число доступных процессоров
- `--memory M` – лимит памяти

**Пример ручного запуска:**  
```bash
./build/application --command run --algo greedy --input ./build/Graphs --output ./build/Answer --processors 4 --memory 1000
```

### Автоматизированный запуск через скрипт

Скрипт `running_all_experiments.py` позволяет запускать жадные алгоритмы (EFT или STS) на всех подготовленных графах из указанных каталогов. Он автоматически копирует каждый граф в рабочую директорию и выполняет бинарный файл `application` с заданными параметрами $P$ и $M$, извлечёнными из имени файла.

**Пример запуска:**  
`python running_all_experiments.py`

> **Необходимые изменения в коде:**  
> В начале файла следует указать:  
> ```python
> directory2 = "/Users/.../build/Graphs"           # рабочая директория для входных графов
> dirs = ['/Users/.../new_layered_time_P_and_M',   # список каталогов с файлами имя_..._P_M.txt
>         '/Users/.../new_random_time_P_and_M',
>         '/Users/.../new_triadags_time_P_and_M']
> algo = 'greedy2'                                 # 'greedy' для EFT, 'greedy2' для STS
> ```  
> Путь `directory2` должен существовать и быть пустым (скрипт очищает его перед каждым запуском).  
> Каталоги в `dirs` должны содержать файлы, сгенерированные на этапе подбора параметров $P$ и $M$ (см. `finding_M_and_P.py`).  
> Внутри цикла для каждого файла извлекаются `P` и `M` из имени (последние два числа, разделённые подчёркиваниями).  
> Вызов бинарного файла `application` – пример:  
> `/Users/.../build/application --command run --algo {algo} --input /Users/.../build/Graphs --output /Users/.../build/Answer --processors {P} --memory {M}`  
> Путь к `application` и все вспомогательные директории должны быть изменены на актуальные.  
> Скрипт пробует запустить алгоритм с множителем памяти `proc = 1`; если не удаётся, можно добавить другие значения (например, `[1, 2, 3]`) для поиска подходящего лимита.

Скрипт `gantt_and_memory.py` строит совмещённое изображение:

- **Диаграмма Ганта** – загрузка процессоров (цветные прямоугольники с номерами работ).  
- **График использования памяти** – ступенчатая диаграмма с отметкой лимита $M$ (красная линия).

**Входные данные:**  
- JSON-файл с расписанием  
- Исходный TXT-файл графа (в новом формате)

**Пример запуска:**  
`python gantt_and_memory.py`

> **Необходимые изменения в коде:**  
> В самом начале скрипта следует задать параметры визуализации:  
> ```python
> file_name = 'g6'                  # имя файла графа (без расширения)

> graphs_dir = f'/Users/.../G/{file_name}.txt'   # путь к исходному графу
> P = 2                             # число процессоров (только для отображения шкалы)
> M = 1500                          # лимит памяти (для красной линии)
> ```  
> Все пути внутри скрипта (к JSON-файлу расписания и к исходному графу) также необходимо привести в соответствие с реальной структурой каталогов.

## **Полный конвейер экспериментов (краткая инструкция)**

0. **Собрать проект** (см. раздел «Сборка проекта»).  
1. **Сгенерировать графы** (layered_generator.py, random_generator.py, triadag_generator.py).  
2. **Конвертировать в новый формат** (converter.py).  
3. **Подобрать $P_{\max}$ и $M_{\max}$** (finding_M_and_P.py) – создаст варианты с $P$ и $M$.  
4. **Транслировать в `.lp`** (run_many_make_inputs_time_for_LP.py) – для запуска ЦЛП.  
5. **Запустить SCIP** (run_many_solvers.py) – для получения оптимальных расписаний.  
6. **Запустить жадные алгоритмы** (running_all_experiments.py) – для получения расписаний EFT/STS.  
7. **Извлечь расписания в JSON** (file_reader_and_making_json.py) – для ЦЛП.  
8. **Визуализировать** (gantt_and_memory.py) – по желанию.

Все скрипты предполагают определённую структуру каталогов (см. исходные комментарии в коде). Для воспроизведения экспериментальных результатов, описанных в работе, рекомендуется использовать приведённые настройки и версии ПО.
```
